# qqq_monitor 首版技术方案

本方案定义 Windows 多功能任务管理器的第一版范围和技术选择。首版交付可持续运行的 CPU、内存、磁盘、网络性能监控，以及二次元像素风格原生 GUI；通过统一指标模型和独立采集接口支持后续扩展。方案编写日期为 2026 年 10 月 4 日，视觉规范于 10 月 5 日按浅色参考图更新，10 月 12 日改为二次元像素风格，并按看板娘角色调整配色。

当前已实现 Workspace、四类核心采集、GPU 利用率、引擎与显存采集、十一个 GUI 页面、Windows 与运行中 WSL 发行版的进程管理、通过 SSH 的 Linux 远程主机监控、前台应用的帧率与帧时间监控、带 Windows 通知的监控告警、边缘吸附迷你状态栏、托盘、历史与配置。已在当前 Windows 11 非管理员账户下验证原生采集和 DX12 启动；性能预算、其他平台兼容性和完整发行验收仍是目标，不能由构建通过推定。实际模块与已验证范围见 [架构设计](ARCHITECTURE.md)，验收清单见 [实施与验收计划](IMPLEMENTATION_PLAN.md)。

## 产品定位与首版范围

产品面向希望快速了解电脑运行状态的 Windows 用户。界面提供简体中文、英语和日语，默认跟随系统显示语言，普通用户权限运行，数据保留在本机。使用习惯保持接近任务管理器，以仪表盘和曲线加强可读性与视觉表现。

| 层级 | 功能 | 首版交付要求 |
| --- | --- | --- |
| 核心 | 系统总览 | CPU、内存、磁盘 I/O、网络四类指标卡片与趋势图 |
| 核心 | CPU 详情 | 总使用率、每个逻辑核心使用率、型号与逻辑核心数 |
| 核心 | 内存详情 | 系统可用物理内存总量、已用、可用、使用率与趋势 |
| 核心 | 磁盘详情 | 本地卷容量与剩余空间；按物理磁盘展示读写速率 |
| 核心 | 网络详情 | 网卡选择、连接状态、实时接收与发送速率、会话流量 |
| 核心 | 历史与设置 | 60 秒、5 分钟、15 分钟视图；采样间隔、动效、窗口设置与开机自动启动 |
| 核心 | 使用体验 | 窗口缩放、DPI 适配、多语言显示、明确的空态和异常状态 |
| 增强 | GPU 监控 | 显卡选择与型号、厂商；最忙引擎利用率与趋势、各类引擎占用、专用与共享显存；迷你状态栏同时展示利用率与显存 |
| 增强 | 迷你状态栏 | 拖到屏幕顶部或左右边缘吸附为置顶迷你状态栏，显示 CPU、内存、GPU、显存 |
| 增强 | 托盘 | 最小化时收进任务栏托盘；吸附为迷你状态栏时移出任务栏并显示托盘图标；单击图标或菜单恢复完整窗口，菜单可退出程序 |
| 增强 | 进程管理 | Windows 与运行中的 WSL 发行版的进程列表、搜索排序、结束进程和优先级调整 |
| 增强 | 远程监控 | 添加一台或多台可用 SSH 登录的 Linux 主机，查看系统信息与 CPU、内存、磁盘、网络、文件系统指标；支持密码、私钥文件与 SSH 代理登录，首次连接核对主机密钥 |
| 增强 | 帧率监控 | 可开关；经 ETW 统计前台应用的帧率、平均与最长帧时间，在帧率页面与迷你状态栏显示；需要管理员权限或 Performance Log Users 组 |
| 增强 | 监控告警 | 为本机与远程主机的设备指标设置高于或低于阈值的规则与持续时间，越过阈值时推送 Windows 通知；规则列表、状态、最近告警与测试通知 |
| 后续扩展 | 自动化与更多工具 | 服务、启动项、历史导出 |

首版不把温度、风扇转速或硬件功耗作为验收条件，进程管理、远程监控、帧率监控、监控告警与 GPU 一样单独评估。这些功能涉及不同权限或硬件数据源，应分别接入，避免拖延核心监控。GPU 计数器不可用的设备上，迷你状态栏的 GPU 与显存显示 `—`，四类核心指标照常发布。

## 技术选型

### GUI 框架比较

下面的结论是针对本项目的工程判断，不是通用性能排名；尚未进行框架性能实测。

| 方案 | 适合本项目的能力 | 需要承担的工作 | 决策 |
| --- | --- | --- | --- |
| egui 与 eframe | 原生 Rust；即时模式便于实时仪表盘与自绘控件；eframe 提供窗口和渲染集成 | 设计统一主题、CJK 字体、多语言文本、动效和图表交互 | 首版采用 |
| Iced | Rust 实现，Elm 风格状态更新，适合结构化应用界面 | 需要熟悉消息模型与自定义组件体系 | 备选，本轮不实现第二套 UI |
| Slint | 声明式界面，适合布局与动画设计 | 引入独立界面描述文件；分发时确认所选许可的要求 | 备选 |
| Tauri | Rust 后端配合 Web 界面，便于使用 Web 设计生态 | 引入前端构建、IPC 和 WebView 运行环境 | 本项目首版优先保持原生 Rust 技术栈 |

eframe 支持 egui 的原生应用集成及 wgpu/glow 渲染器，Iced 官方介绍其 Elm 风格与渲染器。Slint 和 Tauri 的能力与许可说明参见各自官方材料：[eframe 文档](https://docs.rs/eframe/latest/eframe/)、[Iced 仓库](https://github.com/iced-rs/iced)、[Slint 官网](https://slint.dev/)、[Tauri 介绍](https://v2.tauri.app/start/)。

### 采用的组件与依赖边界

| 用途 | 技术 | 放置位置与使用原则 |
| --- | --- | --- |
| 窗口与界面 | eframe、egui | `qqq-ui`；窗口入口由主程序调用 |
| GPU 渲染 | eframe 集成的 wgpu | 首先验证 Windows DX12；不自行重写窗口或渲染引擎 |
| 曲线图 | egui_plot；小型趋势图可用 egui Painter | 统一封装 `HistoryChart`，页面不依赖图表库细节 |
| CPU 与内存 | sysinfo | `qqq-platform-windows`，复用采集实例，只刷新需要的数据 |
| 网卡统计 | Windows IP Helper 的 GetIfTable2 | 同一行获得 LUID、GUID、状态与原始字节，统一进入引擎计算速率 |
| 磁盘 I/O | windows 调用 PDH | 用物理磁盘计数器，避免把多个分区重复当成磁盘 |
| 卷与设备信息 | sysinfo 与 windows | 30 秒采集并过滤网络卷；当前分开显示卷与物理磁盘，映射后续实现 |
| 线程通信 | 标准线程、crossbeam-channel、Mutex、Arc | 有界消息通道与最新快照槽；tokio 只在 `qqq-remote` 中以单线程运行时承载 SSH 连接 |
| SSH 客户端 | russh（ring 加密后端，启用 RSA） | `qqq-remote`；纯 Rust 实现，支持 Ed25519、ECDSA、RSA 私钥、PuTTY 私钥与 OpenSSH 代理，程序自身完成连接与主机密钥核对 |
| 密码存储 | Windows 凭据管理器 | `qqq-platform-windows` 的 `secret.rs`；密码与私钥口令以普通凭据保存，配置文件只保存主机信息 |
| 帧率 | ETW 实时会话，DXGI 与 Direct3D 9 的 Present 事件 | `qqq-platform-windows` 的 `frames.rs`；与 PresentMon、Xbox Game Bar 同源，只读取系统事件；只在开启帧率监控时运行 |
| 通知 | WinRT `ToastNotification`，开始菜单快捷方式上的应用标识 | `qqq-platform-windows` 的 `notify.rs`；引擎的通知线程推送，点击通知打开主窗口 |
| 配置 | serde、toml、directories | `qqq-engine`；UTF-8 TOML，用户目录保存 |
| 日志 | tracing、tracing-subscriber、tracing-appender | 主程序初始化；按日滚动文件，错误限频后续完善 |
| 错误 | thiserror；启动边界可使用 anyhow | 采集错误保持可识别类型，GUI 展示简明信息 |

依赖已在 Workspace 集中声明并生成 Cargo.lock。只启用使用中的 feature；sysinfo 使用 system/disk，网络身份和计数直接通过 IP Helper 获取。

截至方案日期，官方文档显示 eframe 0.36.2、sysinfo 0.39.6、egui_plot 0.37.0，可作为技术验证的候选组合。egui_plot 0.37.0 的清单依赖 egui `^0.36.0`，因此图表库与 egui 的版本号不需要完全相同。sysinfo 文档声明其 MSRV 为 Rust 1.95；这不是整个项目已验证的最低版本。[eframe](https://docs.rs/eframe/latest/eframe/)、[sysinfo](https://docs.rs/sysinfo/latest/sysinfo/)、[egui_plot 清单](https://docs.rs/crate/egui_plot/latest/source/Cargo.toml)。

当前采用 eframe/egui 0.36.2、egui_plot 0.37.0、wgpu 30.0.1、sysinfo 0.39.6、windows 0.62.2、russh 0.64.1（ring 0.17.14）与 tokio 1.53.2。`cargo tree -d` 已检查，egui 与 wgpu 各只有一套版本；其他传递依赖的重复未造成图形类型冲突。本项目使用现有 Git 与 Cargo 工作流，文档和代码持续原地维护。

### 渲染与发行约束

首版选择一条 eframe/wgpu 渲染路径，优先验证 DX12。wgpu 官方文档列出 DX12 等后端，且某些 DX12 着色器编译配置需要 DXC 运行库或静态 DXC feature，因此便携发行包是否能只含一个 EXE 必须通过干净 Windows 环境验证。[wgpu 后端和 DXC 说明](https://docs.rs/wgpu/latest/wgpu/)。

eframe 的 `wgpu_no_default_features` 不会自动启用图形后端；实现时应显式确认实际 feature 图和与 eframe 配套的 wgpu 版本，不能单独加入任意最新 wgpu。首版不假定所有远程桌面、虚拟机或旧显卡都能运行；初始化失败时通过原生错误对话框说明原因并保存日志。[eframe feature 文档](https://docs.rs/eframe/latest/eframe/)。

## 数据采集与指标口径

### 采集频率与数据来源

| 数据组 | 主数据源 | 默认周期 | 说明 |
| --- | --- | --- | --- |
| CPU 使用率与内存 | 持久 sysinfo System | 1 秒 | CPU 首次有效读数需要预热；内存可先显示 |
| 网卡字节计数 | Win32 GetIfTable2 | 1 秒 | 同批获取接口身份；用累计计数差与实际经过时间计算 B/s |
| 物理磁盘读写速率 | PDH PhysicalDisk | 1 秒 | PDH 已格式化的 Bytes/sec 直接作为速率使用 |
| 卷容量 | sysinfo Disks 与 Win32 | 30 秒 | 本地卷列表；与磁盘 I/O 独立显示 |
| 磁盘、网卡设备发现 | PDH 实例数组与 IP Helper | 随采样周期 | 当前直接随性能批次更新；卷目录每 30 秒更新，可手动提前刷新 |
| CPU 型号、系统版本 | sysinfo | 启动时 | 恢复或设备拓扑变化时必要刷新 |
| GPU 利用率与显存 | PDH GPU Engine、GPU Adapter Memory 与 DXGI | 1 秒 | 独立工作线程；计数器出现未知 adapter 时最多每 10 秒重新枚举 |
| 远程主机 | SSH 连接上常驻的 POSIX shell 读取 `/proc`、`/sys` 与 `df` | 跟随采样间隔且至少 1 秒 | 每台主机独立线程；主机信息每次连接读取一次，速率按远程 `/proc/uptime` 计算 |
| 帧率与帧时间 | ETW 中 DXGI 的 Present_Start、PresentMultiplaneOverlay_Start 与 Direct3D 9 的 Present_Start 事件 | 跟随采样间隔 | 开启帧率监控时运行；会话缓冲区写满或每秒交付；统计前台窗口所属进程 |

sysinfo 的 CPU 刷新依赖上一轮状态，复用 System 实例，CPU 刷新间隔不得小于 `MINIMUM_CPU_UPDATE_INTERVAL`。网络使用 GetIfTable2 返回的累计 InOctets/OutOctets，排除 loopback、FilterInterface 和 EndPointInterface，避免将过滤器副本作为另一张网卡。[sysinfo 刷新说明](https://docs.rs/sysinfo/latest/sysinfo/)、[GetIfTable2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getiftable2)、[MIB_IF_ROW2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/ns-netioapi-mib_if_row2)。

PDH 使用 `PdhAddEnglishCounterW` 添加 PhysicalDisk 通配符查询，通过 `PdhGetFormattedCounterArrayW` 获取实例数组和有效状态；本组合已在当前中文 Windows 上得到有效读写数据。成功添加计数器不等于有效读数，首次需要预热，数组每项仍检查 CStatus 和数值范围。[添加英文计数器](https://learn.microsoft.com/en-us/windows/win32/api/pdh/nf-pdh-pdhaddenglishcounterw)、[格式化实例数组](https://learn.microsoft.com/en-us/windows/win32/api/pdh/nf-pdh-pdhgetformattedcounterarrayw)。

### 指标的统一含义

| 指标 | 内部与显示口径 | 边界情况 |
| --- | --- | --- |
| CPU 总使用率 | sysinfo 全局 CPU usage，0 至 100%；逻辑核心单独展示 | 第一轮显示采集中；不从进程 CPU 百分比推算 |
| 内存使用率 | 同一采样中的 `used_memory / total_memory × 100`；容量为字节 | total 为零时不可用；不是机器已安装内存或 Windows 提交量 |
| 卷使用率 | `(total_space - available_space) / total_space × 100` | 显示系统报告的可用空间；权限或配额可能影响口径 |
| 磁盘读写速率 | 物理磁盘的读、写 B/s | 不把卷统计和物理磁盘统计相加；不承诺首版活动时间指标 |
| 网卡速率 | 累计接收/发送字节差除以单调时间差，B/s | 首样本、计数回退、设备重新出现时重新建立基线 |
| 网络会话流量 | 本次应用会话累计观测到的收发字节差 | 不冒充操作系统开机累计值；计数器重置后另建片段并标记缺口 |
| 总览网络 | 默认选中一个活动物理网卡 | VPN、虚拟交换机等可能重复统计；首版不自动相加所有网卡 |
| 系统运行时间 | 系统报告的 uptime，单位秒 | 睡眠相关语义与 Windows 来源一致，不自行改写为应用运行时间 |
| GPU 使用率 | 每个硬件 adapter 先把各进程在同一引擎上的利用率相加，再取最忙引擎，0 至 100% | 第一轮显示采集中；系统未提供该 adapter 的计数器时显示不支持 |
| GPU 引擎占用 | 按计数器引擎类型分组，每类取其中最忙的一个引擎 | 同类多个引擎（如多个复制引擎）不相加；出现过的类型空闲时为 0 |
| 进程 CPU | 同一进程实例在两次快照间使用的处理器时间 ÷（间隔 × 宿主逻辑处理器数）× 100，0 至 100% | 首次出现的进程为空；PID 被复用时按新实例重新计算；WSL 以发行版所在虚拟机的处理器数为基准 |
| 进程内存 | Windows 为专用工作集；WSL 为常驻集（RSS × 页大小） | 两种口径分别对应各自系统的常用显示，不相互换算 |
| 远程 CPU | `/proc/stat` 两次读取间非空闲时钟节拍 ÷ 全部节拍 × 100；I/O 等待单独计算 | 首次读取显示采集中；计数回退重新预热 |
| 远程内存 | 已用为 `MemTotal - MemAvailable`，使用率为已用 ÷ 总量；交换空间按 `SwapTotal`、`SwapFree` | 缺少 `MemAvailable` 的旧内核按 `MemFree + Buffers + Cached` |
| 远程磁盘与网卡 | 扇区数 × 512 与累计字节的增量 ÷ 远程时钟间隔，B/s | 只统计整块物理磁盘，排除 loop、RAM 盘、device-mapper 与软 RAID；网卡排除 `lo` 与容器 `veth` |
| 远程文件系统 | 已用 ÷（已用 + 可用）× 100，与 `df` 的使用率一致 | 只列本地文件系统；同一设备只保留最短挂载点 |
| 帧率 | 本次读取收到的帧间隔求平均，1000 ÷ 平均帧时间 | 统计前台窗口所属进程呈现最多的交换链；前台为本程序时保持上一个应用；停止呈现约 2 秒后为 0；切换应用时重新预热 |
| 帧时间 | 同一交换链相邻两次 Present 调用的间隔，毫秒；同时给出本次读取中最长的一帧 | 与 PresentMon 的 MsBetweenPresents 口径一致；Vulkan 与 OpenGL 程序取决于驱动是否经 DXGI 呈现 |
| 显存 | 专用显存不少于 512 MiB 的 adapter 使用专用显存；集成显卡使用共享 GPU 内存；用量来自 GPU Adapter Memory，总量来自 DXGI；GPU 页面同时列出专用与共享两项 | 用量按物理节点相加；缺少计数器时显示不支持 |

容量 API 和累计网络计数使用 `u64` 字节；当前统一 Gauge 读数转为 `f64`，速率为字节每秒、使用率为百分比，容量为字节。容量显示 MiB/GiB，速率默认 KiB/s、MiB/s；如提供 bit/s 显示选项，显式乘 8。图表横轴按单调时间计算，墙上时钟仅用于日期与日志。

每个指标携带自己的成功采样时刻与状态，状态包括采集中、有效、过期、不支持和采集失败。合法的零流量显示 0，不支持或首次采样显示 `—`，过期值保留但显示更新时间。图表遇到失败或恢复缺口时断线，不用零填充。

### 磁盘与网卡身份

磁盘容量按卷显示，I/O 按物理磁盘显示。卷使用 Windows 卷 GUID，物理磁盘使用当前会话的设备号；一个卷可能跨多个磁盘，关系使用多对多模型。首版优先显示各自数据，无法确认映射时不把 I/O 硬套到盘符。网络卷默认排除；本地可移动设备允许显示容量，I/O 是否存在由能力探测决定。

网卡优先使用 Windows 接口 LUID，名称仅作显示字段。无法建立可靠身份的设备使用会话内 ID，重连后重新预热；不把同名设备的历史拼在一起。网卡选择写入配置时优先保存可跨启动识别的接口 GUID，启动后重新解析为本次 LUID。

### GPU 采集口径

GPU 采集器独立于渲染器，用 DXGI 枚举全部 adapter，取得名称、LUID、专用显存与共享内存总量，展示其中的硬件 adapter；性能计数器按 LUID 对应到 adapter。总使用率按最忙引擎汇总，与 Windows 任务管理器口径一致；3D、Copy、Compute 等引擎类型分别计算后取最大值。Windows 任务管理器的 GPU 数据依赖 WDDM 2.0 及以上驱动，官方也区分专用和共享显存。[Microsoft GPU 指标说明](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/)。

GPU Engine 计数器实例名包含进程 ID、adapter LUID、物理节点、引擎编号与类型，例如 `pid_4_luid_0x00000000_0x0000D1A3_phys_0_eng_0_engtype_3D`；采集器按 adapter 与同一引擎汇总各进程，再取最忙引擎，第一轮预热。GPU Adapter Memory 按 adapter 和物理节点给出整机专用与共享用量，采集器按 adapter 汇总。普通权限即可读取；本机 NVIDIA GeForce RTX 4090 已得到有效利用率与显存读数，集成显卡、混合显卡和虚拟环境另行验证。

NVIDIA、AMD、Intel 厂商 SDK，以及温度、功耗和风扇功能保留为独立采集器扩展。普通权限、混合显卡和虚拟环境无法拿到的数据展示原因，不用管理员权限作为核心功能默认前提。

### 告警页面

工具栏提供「添加告警」与「发送测试通知」，还没有规则时显示说明。每条规则一张卡片：启用勾选框、设备与指标、条件与持续时间、当前值，以及状态（正常、越过阈值后的倒计时、告警中及已持续时间、等待数据、已停用），右侧为编辑与删除。「最近告警」列出本次运行触发的告警与时间。

### 远程主机页面

页面顶部列出已添加的主机，每台主机前的色块表示连接状态（绿色已连接、灰色连接中、红色失败），末尾为“添加主机”按钮；还没有主机时显示说明。选中主机后，连接卡片显示名称、`用户@地址:端口` 与登录方式、连接状态与失败原因，右侧为重新连接、编辑和删除；主机密钥待确认时显示 SHA-256 指纹与“信任并连接”，密钥改变时以警告色说明可能的原因并提供“信任新密钥”。

下方依次为 CPU（附 I/O 等待与进程数）、内存、磁盘读取（镜像显示写入）和网络接收（镜像显示发送）四张指标卡，CPU 与内存趋势图及其右侧的设备档案（主机名、操作系统、架构与内核、处理器、逻辑核心、内存总量、交换空间、系统运行、平均负载），磁盘与网卡选择器及所选网卡的详情，磁盘读写与网络收发两张趋势图，文件系统容量卡片和逻辑核心热力格。网卡默认选中默认路由所在接口，长挂载点保留末尾并以省略号开头。

添加和编辑对话框包含名称、地址、端口、用户名、登录方式（密码、私钥文件、SSH 代理）以及对应的密码、私钥路径与口令；添加时可从 `~/.ssh/config` 导入主机。编辑时密码与口令留空表示保留已保存的值；切换到不需要该密码的登录方式时删除已保存的密码。删除主机前弹出确认。主机列表在保存、信任密钥或删除时立即写入配置；采集在后台持续进行，与当前显示的页面无关。

总览卡片可点击进入详情，并汇总 CPU、内存、所选磁盘读写和所选网卡收发；设备档案集中显示处理器、核心数、内存总量、当前磁盘、当前网卡和系统运行时间。CPU 页面显示总使用率、最忙核心、整体趋势与逻辑核心热力网格；内存页面显示已用、可用与总量；GPU 页面选择显卡并显示厂商、显存类型和 LUID，指标卡给出使用率（附最忙引擎）与显存，趋势图同时绘制 GPU、显存和点选的引擎，引擎热力格列出 3D、复制、视频解码、视频编码等各类引擎，显存明细分列专用显存与共享 GPU 内存；磁盘页面选择物理磁盘查看读写，并同时列出全部本地卷的容量；网络页面始终标明选中的网卡，在指标卡中显示本次会话流量，避免把某个接口速率误认为整机总速率；设置页面不显示时间范围选择。

### 图表、窗口和可访问性

- 图表支持悬停读数、时间范围切换和图例；百分比固定 0 至 100，速率轴自适应并保持短期稳定。

- 默认使用原生标题栏，保留系统拖拽、缩放、最大化和贴靠行为。纯移动后松开鼠标时，窗口若触及没有相邻显示器的顶部、左侧或右侧工作区边缘，即吸附为迷你状态栏；设置页可关闭这一行为。
- 完整窗口最小化时默认隐藏到任务栏托盘，只保留托盘图标；设置页可改为普通最小化。托盘图标悬停显示窗口标题，单击或选择右键菜单的“显示主窗口”恢复并激活窗口，“退出”经正常关闭流程保存配置。
- 设置页可开启开机自动启动：程序以 `--autostart` 参数加入当前用户的 Windows 启动项；开关状态与任务管理器“启动应用”页一致，勾选或取消立即生效。“开机启动时直接收进托盘”默认开启，登录后不显示窗口，只显示托盘图标，单击图标恢复完整窗口；关闭这一项时，登录后按上次关闭时的完整窗口或迷你状态栏启动。
- 数据变化、输入或动画进行时重绘；静止时不持续请求 60 FPS。短动画目标 60 FPS，可关闭以减少开销。
- 最小化时停止装饰动画、降低界面刷新，核心采样继续以原间隔进行，保证历史口径稳定。

## 配置、日志与数据保存

用户配置放入 `directories` 解析的用户配置目录，Windows 上通常为 `%APPDATA%\qqq_monitor\config\config.toml`；日志使用用户本地数据目录，通常为 `%LOCALAPPDATA%\qqq_monitor\data\logs`。实际路径通过库解析，代码不硬编码账户目录。

配置当前保存界面语言、动效、采样间隔、历史视图、网卡选择、窗口尺寸和位置、边缘吸附开关、最小化到托盘开关、开机启动时收进托盘开关、吸附边缘与迷你状态栏位置、帧率监控开关、远程主机列表（地址、端口、用户名、登录方式、私钥路径与信任的主机密钥）以及告警规则（设备身份、指标、条件、阈值、持续时间与启用状态），主题固定为浅色。通知所需的开始菜单快捷方式 `QQQ Monitor.lnk` 位于当前用户的开始菜单程序目录，在打开告警页面或推送通知时创建或更新。开机自动启动保存在当前用户的 Windows 启动项中，由设置页直接读取和开关。远程主机的密码与私钥口令保存在 Windows 凭据管理器，凭据名称为 `qqq_monitor/ssh/主机ID`。关闭时处于吸附状态，下次直接以迷你状态栏启动，并保存吸附前的完整窗口几何信息。设置先在内存中校验并应用，再由后台写入同目录临时文件、刷新并关闭文件句柄，然后替换目标文件。`std::fs::rename` 支持替换已存在的目标文件，仍需处理权限、文件占用和实际文件系统的错误；不能先删除旧配置再移动新文件。失败时保留最后有效配置，并在界面说明本次设置未保存。[Rust 文件替换说明](https://doc.rust-lang.org/std/fs/fn.rename.html)。

配置文件缺失使用默认值，个别字段无效按字段恢复默认，文件语法损坏时保留原文件并提示原因。首次恢复默认期间不自动覆盖损坏文件，用户保存新的设置时才写入。配置只保存偏好，历史指标默认只保留内存；首版不引入数据库。

日志按日滚动，当前最多保留 7 个文件，目录不可写时回退标准错误。丢批与采集错误可在设置页诊断查看。采集耗时 p95、重复错误日志限频和 20 MiB 总量硬限制列入后续稳定性工作。默认不记录网卡 MAC、IP、账户名或进程命令行。

## 性能预算与验收方法

以下是首版目标，均需 Release 构建实测。参考设备为 Windows 11、4 个物理核心与至少 8 个逻辑核心、16 GiB 内存、SSD、支持选定后端的 GPU。CPU 数值按整机全部逻辑核心容量归一化，不能混用单核口径。

| 项目 | 首版目标 | 测量条件 |
| --- | --- | --- |
| 首屏 | 暖启动 2 秒内出现可交互窗口 | 设备发现后台进行；首次驱动初始化另记录 |
| 初次核心数据 | 首屏后约两个采样周期内出现 CPU 与网络有效数据 | 等待差分预热；异常环境显示原因 |
| 常态 CPU | 平均不超过整机 1%；短动画期间目标不超过 3% | 默认 1 秒采样，总览页，预热后连续 5 分钟 |
| 内存 | 稳态工作集目标不超过 180 MiB | 参考设备、默认保留范围；与图形驱动占用一起实测 |
| 历史内存 | 原始历史数据预算 16 MiB | 15 分钟时间上限、点数上限、全局预算共同约束 |
| GUI 响应 | 一般输入至反馈目标不超过 100 ms | 采集变慢或失败时界面仍可操作 |
| CPU 与网络采集 | 快速组采集耗时 p95 小于 100 ms | 正常参考设备；慢磁盘和 GPU 与其隔离 |
| 关闭 | 正常工作线程在 2 秒内结束 | 同步 API 异常阻塞的处理另见架构设计 |
| 长时间运行 | 连续 8 小时无崩溃，无持续内存增长 | 热插拔、最小化恢复和睡眠恢复均纳入检查 |

指标正确性先和相同 API 口径、相同采样区间的参考值比较，再与 Windows 任务管理器观察趋势。系统任务管理器可能使用不同刷新间隔和指标算法，不能把瞬时数值不完全相等直接判为错误，也不能只凭曲线看起来相似判为正确。

## 主要风险与应对

| 风险 | 应对及实施检查 |
| --- | --- |
| GUI 和图表库升级改变接口 | 集中声明依赖；图表封装单一入口；在技术验证中确认版本配套 |
| GPU 或 PDH 不可用 | 能力探测、读数状态检查；局部失败不阻塞核心指标 |
| CJK 字体影响体积或出现缺字 | 验证字体子集与后备方案；加入真实中文、日文设备名称与三种界面语言检查 |
| 远程桌面或显卡初始化失败 | 验证目标场景；失败给出原生提示与日志，不宣称未经测试的兼容性 |
| 卷与物理磁盘混淆 | 分开模型、分开 UI；映射无法确认时不推算 |
| 动效让监控器本身占用偏高 | 按需重绘、动画可关闭、最小化降频；用 Release 实测预算 |
| 同步系统 API 长时间阻塞 | 分采集通道、截止时间监测；不把逻辑超时等同于线程被终止 |
| 远程登录失败触发服务器封禁 | 登录被拒、私钥问题与主机密钥待确认时停止自动重试，由用户修改设置或手动重连 |
| 主机冒充与中间人 | 首次连接显示 SHA-256 指纹由用户确认；与信任的密钥或 `known_hosts` 不一致时拒绝连接并警告 |
| 远程命令阻塞或网络变慢 | `df` 只列本地文件系统；连接 15 秒、每次读取 10 秒超时后断开并退避重连，主机线程彼此独立 |
| 读取帧率需要更高权限 | 默认关闭帧率监控；权限不足时说明原因并提供以管理员身份重新启动；与 PresentMon 同源，只读取系统事件，与反作弊机制兼容 |
| 通知横幅不出现 | 以开始菜单快捷方式登记应用标识；提供测试通知；系统关闭本程序通知时在状态栏说明 |
| 告警频繁打扰 | 持续时间去抖，恢复同样计时，同一规则两次通知至少间隔 1 分钟 |

核心采集和 GUI 已接通，下一步按 [实施与验收计划](IMPLEMENTATION_PLAN.md) 完成异常场景、性能预算和干净环境发行检查。
