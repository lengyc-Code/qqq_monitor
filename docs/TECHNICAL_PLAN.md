# qqq_monitor 首版技术方案

本方案定义 Windows 多功能任务管理器的第一版范围和技术选择。首版交付可持续运行的 CPU、内存、磁盘、网络性能监控，以及深色科技风原生 GUI；通过统一指标模型和独立采集接口支持后续扩展。方案编写日期为 2026 年 10 月 4 日。

当前已实现 Workspace、四类核心采集、六个 GUI 页面、历史与配置。已在当前 Windows 11 非管理员账户下验证原生采集和 DX12 启动；性能预算、其他平台兼容性和完整发行验收仍是目标，不能由构建通过推定。实际模块见 [架构设计](ARCHITECTURE.md)，实测范围见 [验证记录](VALIDATION.md)。

## 产品定位与首版范围

产品面向希望快速了解电脑运行状态的 Windows 用户。首版默认使用中文界面，普通用户权限运行，数据保留在本机。使用习惯保持接近任务管理器，以仪表盘和曲线加强可读性与视觉表现。

| 层级 | 功能 | 首版交付要求 |
| --- | --- | --- |
| 核心 | 系统总览 | CPU、内存、磁盘 I/O、网络四类指标卡片与趋势图 |
| 核心 | CPU 详情 | 总使用率、每个逻辑核心使用率、型号与逻辑核心数 |
| 核心 | 内存详情 | 系统可用物理内存总量、已用、可用、使用率与趋势 |
| 核心 | 磁盘详情 | 本地卷容量与剩余空间；按物理磁盘展示读写速率 |
| 核心 | 网络详情 | 网卡选择、连接状态、实时接收与发送速率、会话流量 |
| 核心 | 历史与设置 | 60 秒、5 分钟、15 分钟视图；采样间隔、动效和窗口设置 |
| 核心 | 使用体验 | 窗口缩放、DPI 适配、中文显示、明确的空态和异常状态 |
| 可选增强 | GPU 监控 | 型号、引擎利用率、专用与共享显存；先完成原生 API 验证 |
| 后续扩展 | 进程与任务操作 | 进程列表、搜索排序、结束进程和优先级调整 |
| 后续扩展 | 自动化与更多工具 | 阈值告警、服务、启动项、托盘、悬浮窗、历史导出 |

首版不把进程控制、温度、风扇转速或硬件功耗作为验收条件。这些功能涉及不同权限或硬件数据源，应分别接入，避免拖延核心监控。GPU 验证不通过时，首版仍可按四类核心指标发布，界面说明该能力不可用。

## 技术选型

### GUI 框架比较

下面的结论是针对本项目的工程判断，不是通用性能排名；尚未进行框架性能实测。

| 方案 | 适合本项目的能力 | 需要承担的工作 | 决策 |
| --- | --- | --- | --- |
| egui 与 eframe | 原生 Rust；即时模式便于实时仪表盘与自绘控件；eframe 提供窗口和渲染集成 | 设计统一主题、中文字体、动效和图表交互 | 首版采用 |
| Iced | Rust 实现，Elm 风格状态更新，适合结构化应用界面 | 需要熟悉消息模型与自定义组件体系 | 备选，本轮不实现第二套 UI |
| Slint | 声明式界面，适合布局与动画设计 | 引入独立界面描述文件；分发时确认所选许可的要求 | 备选 |
| Tauri | Rust 后端配合 Web 界面，便于使用 Web 设计生态 | 引入前端构建、IPC 和 WebView 运行环境 | 本项目首版优先保持原生 Rust 技术栈 |

eframe 支持 egui 的原生应用集成及 wgpu/glow 渲染器，Iced 官方介绍其 Elm 风格与渲染器。Slint 和 Tauri 的能力与许可说明参见各自官方材料：[eframe 文档](https://docs.rs/eframe/latest/eframe/)、[Iced 仓库](https://github.com/iced-rs/iced)、[Slint 官网](https://slint.dev/)、[Tauri 介绍](https://v2.tauri.app/start/)。

### 采用的组件与依赖边界

| 用途 | 技术 | 放置位置与使用原则 |
| --- | --- | --- |
| 窗口与界面 | eframe、egui | `qqq-ui`；窗口入口由主程序调用 |
| GPU 渲染 | eframe 集成的 wgpu | 首先验证 Windows DX12；不自行重写窗口或渲染引擎 |
| 曲线图 | egui_plot；小型趋势图可用 egui Painter | 统一封装 `HistoryChart`，页面不依赖图表库细节 |
| CPU 与内存 | sysinfo | `qqq-platform-windows`，复用采集实例，只刷新需要的数据 |
| 网卡统计 | Windows IP Helper 的 GetIfTable2 | 同一行获得 LUID、GUID、状态与原始字节，统一进入引擎计算速率 |
| 磁盘 I/O | windows 调用 PDH | 用物理磁盘计数器，避免把多个分区重复当成磁盘 |
| 卷与设备信息 | sysinfo 与 windows | 30 秒采集并过滤网络卷；当前分开显示卷与物理磁盘，映射后续实现 |
| 线程通信 | 标准线程、crossbeam-channel、Mutex、Arc | 有界消息通道与最新快照槽；首版无需 Tokio |
| 配置 | serde、toml、directories | `qqq-engine`；UTF-8 TOML，用户目录保存 |
| 日志 | tracing、tracing-subscriber、tracing-appender | 主程序初始化；按日滚动文件，错误限频后续完善 |
| 错误 | thiserror；启动边界可使用 anyhow | 采集错误保持可识别类型，GUI 展示简明信息 |

依赖已在 Workspace 集中声明并生成 Cargo.lock。只启用使用中的 feature；sysinfo 使用 system/disk，网络身份和计数直接通过 IP Helper 获取。

截至方案日期，官方文档显示 eframe 0.36.2、sysinfo 0.39.6、egui_plot 0.37.0，可作为技术验证的候选组合。egui_plot 0.37.0 的清单依赖 egui `^0.36.0`，因此图表库与 egui 的版本号不需要完全相同。sysinfo 文档声明其 MSRV 为 Rust 1.95；这不是整个项目已验证的最低版本。[eframe](https://docs.rs/eframe/latest/eframe/)、[sysinfo](https://docs.rs/sysinfo/latest/sysinfo/)、[egui_plot 清单](https://docs.rs/crate/egui_plot/latest/source/Cargo.toml)。

当前采用 eframe/egui 0.36.2、egui_plot 0.37.0、wgpu 30.0.1、sysinfo 0.39.6、windows 0.62.2。`cargo tree -d` 已检查，egui 与 wgpu 各只有一套版本；其他传递依赖的重复未造成图形类型冲突。本项目使用现有 Git 与 Cargo 工作流，文档和代码持续原地维护。

### 渲染与发行约束

首版选择一条 eframe/wgpu 渲染路径，优先验证 DX12。wgpu 官方文档列出 DX12 等后端，且某些 DX12 着色器编译配置需要 DXC 运行库或静态 DXC feature，因此便携发行包是否能只含一个 EXE 必须通过干净 Windows 环境验证。[wgpu 后端和 DXC 说明](https://docs.rs/wgpu/latest/wgpu/)。

eframe 的 `wgpu_no_default_features` 不会自动启用图形后端；实现时应显式确认实际 feature 图和与 eframe 配套的 wgpu 版本，不能单独加入任意最新 wgpu。首版不假定所有远程桌面、虚拟机或旧显卡都能运行；初始化失败时通过原生错误对话框说明原因并保存日志。[eframe feature 文档](https://docs.rs/eframe/latest/eframe/)。

## 数据采集与指标口径

### 采集频率与数据来源

| 数据组 | 主数据源 | 默认周期 | 说明 |
| --- | --- | --- | --- |
| CPU 使用率与内存 | 持久 sysinfo System | 1 秒 | CPU 首次有效读数需要预热；内存可先显示 |
| 网卡字节计数 | Win32 GetIfTable2 | 1 秒 | 同批获取接口身份；用累计计数差与实际经过时间计算 B/s |
| 物理磁盘读写速率 | PDH PhysicalDisk | 1 秒 | PDH 已格式化的 Bytes/sec 直接作为速率使用 |
| 卷容量 | sysinfo Disks 与 Win32 | 30 秒 | 本地卷列表；与磁盘 I/O 独立显示 |
| 磁盘、网卡设备发现 | PDH 实例数组与 IP Helper | 随采样周期 | 当前直接随性能批次更新；卷目录每 30 秒更新，可手动提前刷新 |
| CPU 型号、系统版本 | sysinfo | 启动时 | 恢复或设备拓扑变化时必要刷新 |
| GPU 指标，可选 | PDH 与 DXGI | 1 秒；发现 10 秒 | 独立工作线程，能力验证后启用 |

sysinfo 的 CPU 刷新依赖上一轮状态，复用 System 实例，CPU 刷新间隔不得小于 `MINIMUM_CPU_UPDATE_INTERVAL`。网络使用 GetIfTable2 返回的累计 InOctets/OutOctets，排除 loopback、FilterInterface 和 EndPointInterface，避免将过滤器副本作为另一张网卡。[sysinfo 刷新说明](https://docs.rs/sysinfo/latest/sysinfo/)、[GetIfTable2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getiftable2)、[MIB_IF_ROW2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/ns-netioapi-mib_if_row2)。

PDH 使用 `PdhAddEnglishCounterW` 添加 PhysicalDisk 通配符查询，通过 `PdhGetFormattedCounterArrayW` 获取实例数组和有效状态；本组合已在当前中文 Windows 上得到有效读写数据。成功添加计数器不等于有效读数，首次需要预热，数组每项仍检查 CStatus 和数值范围。[添加英文计数器](https://learn.microsoft.com/en-us/windows/win32/api/pdh/nf-pdh-pdhaddenglishcounterw)、[格式化实例数组](https://learn.microsoft.com/en-us/windows/win32/api/pdh/nf-pdh-pdhgetformattedcounterarrayw)。

### 指标的统一含义

| 指标 | 内部与显示口径 | 边界情况 |
| --- | --- | --- |
| CPU 总使用率 | sysinfo 全局 CPU usage，0 至 100%；逻辑核心单独展示 | 第一轮显示采集中；不从进程 CPU 百分比推算 |
| 内存使用率 | 同一采样中的 `used_memory / total_memory × 100`；容量为字节 | total 为零时不可用；不是机器已安装内存或 Windows 提交量 |
| 卷使用率 | `(total_space - available_space) / total_space × 100` | 显示系统报告的可用空间；权限或配额可能影响口径 |
| 磁盘读写速率 | 物理磁盘的读、写 B/s | 不把卷统计和物理磁盘统计相加；不承诺首版活动时间指标 |
| 网卡速率 | 累计接收/发送字节差除以单调时间差，B/s | 首样本、计数回退、设备重新出现时重新建立基线 |
| 网络会话流量 | 本次应用会话累计观测到的收发字节差 | 不冒充操作系统开机累计值；计数器重置后另建片段并标记缺口 |
| 总览网络 | 默认选中一个活动物理网卡 | VPN、虚拟交换机等可能重复统计；首版不自动相加所有网卡 |
| 系统运行时间 | 系统报告的 uptime，单位秒 | 睡眠相关语义与 Windows 来源一致，不自行改写为应用运行时间 |

容量 API 和累计网络计数使用 `u64` 字节；当前统一 Gauge 读数转为 `f64`，速率为字节每秒、使用率为百分比，容量为字节。容量显示 MiB/GiB，速率默认 KiB/s、MiB/s；如提供 bit/s 显示选项，显式乘 8。图表横轴按单调时间计算，墙上时钟仅用于日期与日志。

每个指标携带自己的成功采样时刻与状态，状态包括采集中、有效、过期、不支持和采集失败。合法的零流量显示 0，不支持或首次采样显示 `—`，过期值保留但显示更新时间。图表遇到失败或恢复缺口时断线，不用零填充。

### 磁盘与网卡身份

磁盘容量按卷显示，I/O 按物理磁盘显示。卷使用 Windows 卷 GUID，物理磁盘使用当前会话的设备号；一个卷可能跨多个磁盘，关系使用多对多模型。首版优先显示各自数据，无法确认映射时不把 I/O 硬套到盘符。网络卷默认排除；本地可移动设备允许显示容量，I/O 是否存在由能力探测决定。

网卡优先使用 Windows 接口 LUID，名称仅作显示字段。无法建立可靠身份的设备使用会话内 ID，重连后重新预热；不把同名设备的历史拼在一起。网卡选择写入配置时优先保存可跨启动识别的接口 GUID，启动后重新解析为本次 LUID。

### GPU 可选增强的限制

GPU 不通过渲染器的 adapter 自动代表整机 GPU。采集器单独枚举硬件 adapter，并通过 LUID 对应性能计数器。总使用率按最忙引擎汇总，各引擎数据分别保留；不能把 3D、Copy、Compute 百分比直接相加。Windows 任务管理器的 GPU 数据依赖 WDDM 2.0 及以上驱动，官方也区分专用和共享显存。[Microsoft GPU 指标说明](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/)。

拟验证 GPU Engine 与 GPU Adapter Memory 计数器的实例、权限和聚合含义。若源数据包含按进程计数，先按 adapter 和同一引擎聚合，再取最忙引擎；显存不得简单累加按进程数据。DXGI 用于身份和设备信息，其进程显存预算 API 不作为整机显存已用量。

NVIDIA、AMD、Intel 厂商 SDK，以及温度、功耗和风扇功能保留为独立采集器扩展。普通权限、混合显卡和虚拟环境无法拿到的数据展示原因，不用管理员权限作为核心功能默认前提。

## GUI 视觉和交互设计

### 视觉方向

采用深色科技风，通过清晰层次、青紫强调色、曲线和短促动效形成视觉识别。首版用不透明分层背景模拟玻璃质感；真实桌面模糊、Mica 与自定义无边框标题栏列为后续增强，避免在基本窗口交互尚未验证时扩大范围。

| 设计项 | 建议值与规则 |
| --- | --- |
| 页面背景 | `#0B1020` |
| 卡片背景 | `#141D30`；悬停层 `#1A2740` |
| 主文字 | `#E7EDF8`；次文字 `#A8B6CE` |
| 指标配色 | CPU 青 `#35D8F5`，内存紫 `#A78BFA`，磁盘蓝 `#60A5FA`，网络绿 `#34D399` |
| 警告与错误 | 黄 `#FBBF24`、红 `#F87171`，同时使用图标和文字 |
| 间距 | 8、12、16、24、32 逻辑像素 |
| 卡片 | 12 像素圆角；细边框、轻阴影；正文保持高对比度 |
| 文字层次 | 正文 14、卡片标题 16、页面标题 24、主指标 32 至 40 |
| 动效 | 150 至 220 ms 的悬停、选择与页面过渡；可关闭 |

当前嵌入完整的 Noto Sans CJK SC Regular，约 15.7 MiB，保留 OFL 许可文件，避免固定文案子集遗漏真实设备名称。默认字体作为补充，当前中文与设备名称已在 150% DPI 截图中检查；完整特殊字符覆盖、多屏缩放和字体体积优化仍待验证。[Noto CJK 字体许可](https://github.com/notofonts/noto-cjk/blob/main/Sans/LICENSE)。

导航首版只显示已实现页面。GPU 能力可用且增强项已交付时再显示对应页面；不预先放置无法使用的进程、服务导航。

总览卡片可点击进入详情。CPU 页面显示整体趋势与逻辑核心热力网格；磁盘页面分别选择物理磁盘和卷；网络页面始终标明选中的网卡，避免把某个接口速率误认为整机总速率。

### 图表、窗口和可访问性

- 图表支持悬停读数、时间范围切换和图例；百分比固定 0 至 100，速率轴自适应并保持短期稳定。
- 数值显示真实采样结果。动效可以平滑视觉变化，但历史曲线只使用实际采样点，不制造额外数据。
- 多序列使用颜色与线型共同区分；失败、过期状态用文字说明。
- 当前 1280 × 800 总览使用四列卡片，较窄窗口切换为两列并滚动；最小窗口为 960 × 640，DPI 变化按逻辑像素处理。
- 中文、键盘焦点、基础键盘导航与高对比度必须人工检查；保留 eframe 的可访问性能力。
- 默认使用原生标题栏，保留系统拖拽、缩放、最大化和贴靠行为。
- 数据变化、输入或动画进行时重绘；静止时不持续请求 60 FPS。短动画目标 60 FPS，可关闭以减少开销。
- 最小化时停止装饰动画、降低界面刷新，核心采样继续以原间隔进行，保证历史口径稳定。

## 配置、日志与数据保存

用户配置放入 `directories` 解析的用户配置目录，Windows 上通常为 `%APPDATA%\qqq_monitor\config\config.toml`；日志使用用户本地数据目录，通常为 `%LOCALAPPDATA%\qqq_monitor\data\logs`。实际路径通过库解析，代码不硬编码账户目录。

配置当前保存动效、采样间隔、历史视图、网卡选择、窗口尺寸和位置，主题固定为深色。设置先在内存中校验并应用，再由后台写入同目录临时文件、刷新并关闭文件句柄，然后替换目标文件。`std::fs::rename` 支持替换已存在的目标文件，仍需处理权限、文件占用和实际文件系统的错误；不能先删除旧配置再移动新文件。失败时保留最后有效配置，并在界面说明本次设置未保存。[Rust 文件替换说明](https://doc.rust-lang.org/std/fs/fn.rename.html)。

配置文件缺失使用默认值，个别字段无效按字段恢复默认，文件语法损坏时保留原文件并提示原因。首次恢复默认期间不自动覆盖损坏文件，用户保存新的设置时才写入。配置只保存偏好，历史指标默认只保留内存；首版不引入数据库。

日志按日滚动，当前最多保留 7 个文件，目录不可写时回退标准错误。丢批与采集错误可在设置页诊断查看。采集耗时 p95、重复错误日志限频和 20 MiB 总量硬限制列入后续稳定性工作。默认不记录网卡 MAC、IP、账户名或进程命令行。

## 性能预算与验收方法

以下是首版目标，均需 Release 构建实测。参考设备为 Windows 11、4 个物理核心与至少 8 个逻辑核心、16 GiB 内存、SSD、支持选定后端的 GPU。CPU 数值按整机全部逻辑核心容量归一化，不能混用单核口径。

| 项目 | 首版目标 | 测量条件 |
| --- | --- | --- |
| 首屏 | 暖启动 2 秒内出现可交互窗口 | 设备发现后台进行；首次驱动初始化另记录 |
| 初次核心数据 | 首屏后约两个采样周期内出现 CPU 与网络有效数据 | 等待差分预热；异常环境显示原因 |
| 常态 CPU | 平均不超过整机 1%；短动画期间目标不超过 3% | 默认 1 秒采样，总览页，预热后连续 5 分钟 |
| 内存 | 稳态工作集目标不超过 180 MiB | 参考设备、默认保留范围；与图形驱动占用一起实测 |
| 历史内存 | 原始历史数据预算 16 MiB | 15 分钟时间上限、点数上限、全局预算共同约束 |
| GUI 响应 | 一般输入至反馈目标不超过 100 ms | 采集变慢或失败时界面仍可操作 |
| CPU 与网络采集 | 快速组采集耗时 p95 小于 100 ms | 正常参考设备；慢磁盘和 GPU 与其隔离 |
| 关闭 | 正常工作线程在 2 秒内结束 | 同步 API 异常阻塞的处理另见架构设计 |
| 长时间运行 | 连续 8 小时无崩溃，无持续内存增长 | 热插拔、最小化恢复和睡眠恢复均纳入检查 |

指标正确性先和相同 API 口径、相同采样区间的参考值比较，再与 Windows 任务管理器观察趋势。系统任务管理器可能使用不同刷新间隔和指标算法，不能把瞬时数值不完全相等直接判为错误，也不能只凭曲线看起来相似判为正确。

## 主要风险与应对

| 风险 | 应对及实施检查 |
| --- | --- |
| GUI 和图表库升级改变接口 | 集中声明依赖；图表封装单一入口；在技术验证中确认版本配套 |
| GPU 或 PDH 不可用 | 能力探测、读数状态检查；局部失败不阻塞核心指标 |
| 中文字体影响体积或出现缺字 | 验证字体子集与后备方案；加入真实中文设备名称检查 |
| 远程桌面或显卡初始化失败 | 验证目标场景；失败给出原生提示与日志，不宣称未经测试的兼容性 |
| 卷与物理磁盘混淆 | 分开模型、分开 UI；映射无法确认时不推算 |
| 动效让监控器本身占用偏高 | 按需重绘、动画可关闭、最小化降频；用 Release 实测预算 |
| 同步系统 API 长时间阻塞 | 分采集通道、截止时间监测；不把逻辑超时等同于线程被终止 |

核心采集和 GUI 已接通，下一步按 [实施与验收计划](IMPLEMENTATION_PLAN.md) 完成异常场景、性能预算和干净环境发行检查，再扩展进程管理与可选 GPU。
