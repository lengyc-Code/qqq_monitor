# qqq_monitor 首版实施与验收计划

本计划把 [技术方案](TECHNICAL_PLAN.md) 与 [架构设计](ARCHITECTURE.md) 转为可执行开发阶段。按技术验证、基础模块、真实采集、完整 GUI、发布检查推进；每个阶段以可演示结果和运行时证据作为完成条件。

当前已建立 Workspace、监控引擎、四类核心采集、GPU 采集、十二个 GUI 页面、Windows 与 WSL 进程管理、通过 SSH 的 Linux 远程主机监控、前台应用的帧率监控、监控告警与 Windows 通知、快捷键截图、剪贴板管理、置顶便签与快捷指令、边缘吸附迷你状态栏、托盘驻留和开机自动启动。已经通过 95 项自动测试（另有 2 项忽略标记测试：需运行中 WSL 发行版的进程操作测试，以及会显示一条桌面通知的通知测试）、fmt、Clippy、Release 构建，以及 Windows 11 非管理员账户的真实采集和页面截图检查；已验证范围见 [架构设计](ARCHITECTURE.md) 的验证边界。下面的条目仍是完整首版验收清单，未验证项不因模块已实现而自动通过。

## 阶段一 建立模块和引擎骨架

将根包改为 Workspace 启动入口，建立四个库 crate，集中依赖和 lint。定义设备、指标、单位、状态、CollectorFactory、MonitorClient 和 MonitorRuntime；用假采集器驱动引擎。

实现有界通道、最新 Arc 视图槽、差分与预热、历史时间与容量限制、命令确认和独立取消信号。引擎不能依赖平台或 GUI crate，领域层不能引入系统调用。

完成条件：

- Workspace 可以编译，依赖图符合设计。
- 假采集器能生成真实时间戳的快照与历史投影。
- 某个采集器失败或变慢时其他通道继续更新。
- GUI 暂不消费视图时，采样历史仍正常记录，显示快照不积压。
- 通道满载、历史预算触发和退出行为有运行时验证。

## 阶段二 接入四类核心采集

先实现 CPU 与内存，再实现网卡计数和身份，最后实现物理磁盘 PDH、卷容量与设备发现。采集对象在自己的工作线程创建；Windows API 句柄使用 RAII 释放。

完成条件：

- CPU 总体和逻辑核心、内存、磁盘读写、卷容量、网卡收发都有来源明确的有效读数。
- 第一轮差分数据为采集中，累计计数回退和恢复不会生成尖峰。
- 同一 SSD 的多个分区不会重复加总物理磁盘 I/O；网络总览显示明确选择的接口。
- 本地卷和物理盘无法确认映射时，界面数据保持分开；网络卷默认排除。
- 热插拔、网卡断连和重命名会更新目录，旧数据有明确离线或过期状态。
- 普通用户权限运行核心功能；某项权限受限时报告该项原因。

## 阶段三 完成 GUI 和使用体验

先建立应用壳、主题、字体与通用组件，再完成总览、CPU、内存、磁盘、网络和设置页面。图表只消费引擎投影，设置通过命令应用和保存。

完成条件：

- 首屏四类卡片、详情页与历史范围切换可操作，所有数字来自采样结果。
- 配色、间距、文字层次和状态展示使用统一组件。
- 三种界面语言、长设备名称、最小窗口、最大化及 100%、150%、200% DPI 可读；跟随系统与手动切换语言均正确。
- 悬停读数、选中设备、键盘焦点和基础导航工作正常。
- 加载、不支持、失败、过期、设备消失状态均有可理解的界面反馈。
- 动效可关闭；最小化停止装饰动效，后台采样与历史连续。
- 设置重启后恢复，保存失败时明确区分已应用与未保存。
- 窗口拖到顶部、左侧、右侧开放边缘后吸附为迷你状态栏；系统贴靠、最大化和相邻显示器一侧保持系统行为；迷你状态栏可沿边缘移动、换边、拖离或双击恢复，关闭后按吸附状态重启。
- 吸附期间任务栏只保留托盘图标；开启“最小化到托盘”时，最小化的完整窗口隐藏到托盘。单击托盘图标或选择菜单的“显示主窗口”恢复完整窗口，菜单的“退出”保存配置并移除图标；资源管理器重启后图标与任务栏状态恢复。
- 设置页的开机自动启动显示当前用户启动项的实际状态：开启后重新登录 Windows 会启动程序；在任务管理器中禁用后显示为关闭，再次开启恢复启动；关闭后启动项移除。开启“开机启动时直接收进托盘”（默认）时，登录后只出现托盘图标，没有窗口闪现，单击图标恢复完整窗口；关闭这一项时按上次关闭时的状态显示窗口。
- GPU 页面可切换显卡、点击引擎查看历史；迷你状态栏随所选显卡更新。
- 进程页面列出 Windows 与每个运行中 WSL 发行版的进程，可搜索、排序、确认后结束进程和调整优先级；离开页面后停止轮询，查看发行版不会启动已停止的发行版；权限不足、进程已退出和发行版停止均在状态栏说明。
- 远程页面可添加、编辑和删除多台 Linux 主机，可从 `~/.ssh/config` 导入；密码、私钥文件与 SSH 代理三种登录方式可用，密码与口令只进入 Windows 凭据管理器。首次连接显示主机密钥指纹并由用户信任，密钥改变时拒绝连接并警告。各主机的系统信息、CPU、内存、磁盘、网卡、文件系统与逻辑核心有来源明确的读数；断线后自动重连，登录被拒等需要用户处理的失败不自动重试；删除主机后不留设备、读数与密码。
- 帧率页面与设置页面可开关帧率监控：开启后统计前台应用的帧率、平均与最长帧时间，前台为本程序时保持上一个应用，切换应用时曲线留出缺口；权限不足时说明原因并可以管理员身份重新启动；关闭后停止事件跟踪；迷你状态栏随开关增减 FPS 一项并调整尺寸。
- 告警页面可添加、编辑、启用、停用与删除规则，指标随所选设备列出，阈值按指标单位输入并换算保存；越过阈值并保持持续时间后推送 Windows 通知，回到另一侧并保持同样时间后恢复，同一规则 1 分钟内只通知一次；窗口在托盘或吸附时同样推送，点击通知恢复主窗口；状态栏显示触发中的规则数；测试通知可用，系统关闭通知时给出说明。
- 截图快捷键、小工具页面的「开始截图」与托盘菜单都能开始截图，窗口收进托盘或吸附时快捷键同样可用；拖动选区后剪贴板与保存的 PNG 内容一致，单击截取整个显示器，Esc 与右键取消时剪贴板与截图目录保持原样；小工具页面列出、复制、打开与删除截图，超出保留数量时删除最早的截图；页面截图时主窗口不出现在截图中；组合键被占用时状态栏说明原因；更换快捷键后新组合键立即生效。
- 小工具页面的剪贴板与设置页面可开关剪贴板管理：开启后记录复制的文本、图片与文件，再次复制已有内容时把那条记录移到最前，一键复制回剪贴板后可在其他程序粘贴；超出保留数量或内存上限时移除最早的记录；标记为隐私的内容被跳过；退出后记录清空。
- 便签快捷键、小工具页面的「打开便签」与托盘菜单都能显示便签窗口，主窗口最小化、收进托盘或吸附时同样可用；便签窗口位于其他窗口之上并取得键盘焦点，在便签中再按快捷键隐藏；Markdown 在编辑时着色、在预览中渲染，勾选任务写回原文；停止输入后便签写入 `notes` 目录，退出前的输入同样保存；新建、切换与确认后删除便签；拖动移动与调整大小后，下次启动按保存的位置与尺寸显示；与另一个快捷键相同的组合键在录制时给出提示。
- 快捷指令的快捷键与小工具页面的「运行」都能运行快捷指令，窗口收进托盘或吸附时快捷键同样可用；「在同一会话中依次运行」时全部命令在一个 PowerShell 会话中按顺序执行，后面的命令沿用前面设置的变量与位置；「每条命令一个会话」时每条命令在各自的会话中同时运行；显示窗口时窗口标题为快捷指令名称，命令结束后窗口保留，后台运行时会话在后台执行并随命令结束退出；填写的工作目录生效，留空时从用户文件夹开始；新建、编辑与确认后删除快捷指令立即保存，删除后其余快捷指令的快捷键继续有效；与其他任一快捷键相同的组合键在录制时给出提示；会话启动失败时状态栏说明原因；每次运行播放提示音（可关闭），窗口收进托盘或吸附时弹出显示结果的托盘气泡，点击气泡打开主窗口。

## 阶段四 稳定性与发行检查

用 Release 构建完成性能测量和长时间运行，按需要修复现有实现。整理便携包、字体许可和第三方许可，确认运行库依赖。

| 场景 | 检查方法 | 合格结果 |
| --- | --- | --- |
| 正常资源占用 | 参考设备预热后运行 5 分钟，记录整机归一化 CPU 与工作集 | 达到技术方案预算，超出时有实测原因与修正 |
| 8 小时运行 | 保持默认采样，检查工作集、线程数和错误量 | 无持续增长，无崩溃；历史与日志上限生效 |
| 睡眠恢复 | 睡眠后恢复，继续观察网络和磁盘 | 无恢复尖峰；有缺口和重新预热状态 |
| GUI 暂停消费 | 假 UI/测试客户端停止读取视图后恢复 | 正常采样仍入历史，恢复直接显示最近数据 |
| 慢采集 | 假采集器延迟超过多个周期 | 快速组仍更新，慢组变为过期，无无限重启线程 |
| 热插拔与断连 | 可移动盘、网卡断开与重连 | 无崩溃、身份不误合并、不支持数据不冒充 0 |
| 配置故障 | 无效字段、损坏 TOML、只读目录 | 默认或保留有效状态，原损坏文件不被自动覆盖 |
| 关闭 | 正常退出和模拟阻塞调用 | 正常线程 2 秒内结束；阻塞场景不无限等待 |
| 干净 Windows 环境 | 未安装 Rust 和开发工具的机器或虚拟机 | 便携包按说明直接运行，缺失组件有明确处理 |
| Windows 10 与远程桌面 | 在实际环境执行启动与主要交互 | 单独记录通过与局限，只有通过后才声明兼容 |

## 需要编写的运行时测试

以下测试针对不能只靠阅读代码确认的状态变化。普通 UI 组合、简单构造函数和直接字段转发不机械添加测试。

| 测试重点 | 具体断言 |
| --- | --- |
| 差分时间 | 1.2 秒内增加 1200 字节得到 1000 B/s，而不是按固定一秒计算 |
| 基线与回退 | 第一轮无速率；10000 回退到 100 后重新预热，不发生下溢或巨幅流量 |
| 源类型 | PDH 已格式化 B/s 直接入视图，不被第二次求差分 |
| 局部失败 | 网卡失败不会清空 CPU、内存；合法零流量仍保持 Ready |
| GPU 聚合 | 同一引擎的各进程利用率相加并截断到 100%；每类引擎取最忙的一个，总使用率取最忙引擎；显存按物理节点相加 |
